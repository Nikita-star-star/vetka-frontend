# Сохранение и сброс состояния

## Почему состояние принадлежит месту в дереве

React не «приклеивает» state к тексту функции. Состояние связано с положением компонента в дереве, его типом и, при необходимости, ключом `key`.

```jsx
import { useState } from 'react';

function Counter() {
  const [value, setValue] = useState(0);
  return <button onClick={() => setValue((x) => x + 1)}>{value}</button>;
}

export default function App() {
  const [show, setShow] = useState(true);
  return (
    <>
      <button onClick={() => setShow((x) => !x)}>Показать / скрыть</button>
      {show && <Counter />}
    </>
  );
}
```

Если скрыть `Counter`, он исчезнет из дерева и его состояние будет потеряно. При повторном появлении это новый экземпляр с начальным нулём. Такое исчезновение называется **размонтированием**; появление — **монтированием**.

## Сброс с key

Иногда компонент остаётся на той же позиции, но мы хотим сбросить его состояние при выборе другого объекта:

```jsx
<Editor key={selectedTaskId} taskId={selectedTaskId} />
```

`Editor` здесь — уже созданный пользователем компонент редактирования, а `selectedTaskId` — ID выбранной задачи. При изменении `key` React рассматривает компонент как новый и создаёт его state заново. Это полезно для формы редактирования разных задач, но нельзя генерировать случайный `key` при каждом рендере: тогда состояние будет сбрасываться постоянно.

## Не путайте сохранение состояния с хранением данных

React-state живёт в памяти интерфейса. Обновление страницы браузера обычно начинает приложение заново. Для постоянного хранения требуется другой механизм — сервер, база данных или браузерное хранилище. Это отдельная задача, не связанная с идентичностью компонентов.

Документация: [Preserving and Resetting State](https://react.dev/learn/preserving-and-resetting-state).

## Почему порядок дерева влияет на состояние

React связывает state с **положением экземпляра компонента в дереве**. Если на том же месте продолжает находиться тот же тип компонента с тем же `key`, state обычно сохраняется. Если компонент удалён или его идентичность изменена, state может сброситься.

```jsx
import { useState } from 'react';

function Editor() {
  const [draft, setDraft] = useState('');
  return <input value={draft} onChange={(event) => setDraft(event.target.value)} />;
}

export default function App() {
  const [selected, setSelected] = useState('a');
  return (
    <>
      <button onClick={() => setSelected('a')}>Черновик А</button>
      <button onClick={() => setSelected('b')}>Черновик Б</button>
      <Editor key={selected} />
    </>
  );
}
```

Когда меняется `selected`, меняется `key` элемента `Editor`. React создаёт новый экземпляр, поэтому строка в поле очищается. Это полезно, если действительно нужно начинать новый черновик, но станет ошибкой, если при каждом нажатии случайно создавать новый `key`.

**Распространённая ошибка:** определять один компонент внутри тела другого компонента. При каждом рендере создаётся новая функция-тип, из-за чего React может сбрасывать его состояние. Объявляйте компоненты на верхнем уровне файла.
