# useEffect и внешние системы

## Когда обычного рендера недостаточно

До сих пор React обрабатывал ввод и вычислял JSX на основании state. Иногда требуется согласовать компонент с чем-то *вне React*: заголовком вкладки браузера, таймером или сетевым соединением.

**Побочный эффект** — действие, которое изменяет что-то вне текущего вычисления. **Хук `useEffect`** позволяет выполнить такую синхронизацию после отображения компонента.

```jsx
import { useState, useEffect } from 'react';

export default function App() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    document.title = `Нажатий: ${count}`;
  }, [count]);

  return (
    <button onClick={() => setCount((previous) => previous + 1)}>
      Нажатий: {count}
    </button>
  );
}
```

`document.title` — свойство браузера, отвечающее за заголовок вкладки. Массив `[count]` — **список зависимостей эффекта**: React заново выполняет синхронизацию, когда `count` изменится.

## Чего не нужно делать через useEffect

Если нужно получить число выполненных задач из `tasks`, вычислите его прямо во время рендера:

```js
const completedCount = tasks.filter((task) => task.done).length;
```

Использовать отдельный state и `useEffect` для такого вычисления не нужно: появляется лишнее обновление и риск рассинхронизации. Если действие вызвано нажатием кнопки, код обычно должен находиться в обработчике этой кнопки.

## Очистка эффекта

Ресурсы вроде таймеров необходимо освобождать. **Очистка** (cleanup) — функция, которую эффект возвращает для завершения предыдущей синхронизации.

```jsx
import { useState, useEffect } from 'react';

export default function Clock() {
  const [seconds, setSeconds] = useState(0);

  useEffect(() => {
    const timerId = setInterval(() => {
      setSeconds((previous) => previous + 1);
    }, 1000);

    return () => clearInterval(timerId);
  }, []);

  return <p>Секунд: {seconds}</p>;
}
```

`setInterval` вызывает функцию через заданные интервалы; `clearInterval` останавливает таймер. Пустой массив `[]` означает, что эффект не зависит от изменяемых props/state. В режиме разработки React может дополнительно выполнить настройку и очистку для проверки корректности эффекта.


## Устаревшее замыкание и зависимости

Внутри эффекта функции читают значения из конкретного рендера. Если эффект использует `query`, то `query` должен быть зависимостью. Если скрыть зависимость, эффект продолжит работать со старым значением или перестанет реагировать на новые props.

Эффект вида `useEffect(() => setCount(count + 1), [count])` может вызвать бесконечный цикл: эффект изменяет зависимость, отчего запускается снова. Сначала подумайте, действительно ли нужна внешняя синхронизация.

**Strict Mode** в разработке может дополнительно вызвать setup и cleanup, чтобы выявить ошибки очистки. Это не «баг двойного запроса», который нужно маскировать глобальной переменной; синхронизация должна правильно завершаться.

## Эффект и события — разные причины выполнения

Отправляйте POST в обработчике формы, если запрос должен происходить только при отправке. Не создавайте флаг `shouldSave` с эффектом, реагирующим на него: событие уже имеет подходящее место для логики.
