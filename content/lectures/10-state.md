# useState и снимок состояния

## Почему обычная переменная не обновляет страницу

Рассмотрим компонент:

```jsx
export default function App() {
  let count = 0;

  function increase() {
    count = count + 1;
    console.log(count);
  }

  return <button onClick={increase}>Нажатий: {count}</button>;
}
```

После нажатия число в консоли изменится, но надпись кнопки останется прежней. Причина: React не узнаёт, что изменение обычной переменной требует нового отображения.

**Состояние (state)** — данные, которые компонент сохраняет между отображениями и изменение которых сообщает React о необходимости обновить интерфейс.

**Хук** — специальная функция React, позволяющая компоненту пользоваться его возможностями. `useState` — хук для состояния.

## Создание состояния

Замените `src/App.jsx`:

```jsx
import { useState } from 'react';

export default function App() {
  const [count, setCount] = useState(0);

  function increase() {
    setCount(count + 1);
  }

  return (
    <button onClick={increase}>
      Нажатий: {count}
    </button>
  );
}
```

`import { useState }` подключает именованный экспорт из React. `useState(0)` задаёт **начальное значение** — ноль. React возвращает массив из двух элементов. Благодаря деструктуризации `count` получает текущее значение, а `setCount` — функцию его изменения.

При нажатии `setCount(count + 1)` сообщает React о новом значении. React снова вызывает компонент и вычисляет JSX с обновлённым `count`. Это **повторный рендер** (render) — повторное получение описания интерфейса. React затем обновляет нужный текст в DOM.

## Состояние — снимок во время рендера

Внутри уже выполняющегося обработчика значение `count` не меняется мгновенно:

```jsx
function increase() {
  setCount(count + 1);
  console.log(count);
}
```

`console.log` покажет значение из текущего рендера. Новое станет доступно при следующем вызове компонента.

Если следующее значение зависит от предыдущего, лучше использовать **функциональное обновление**:

```jsx
function increase() {
  setCount((previous) => previous + 1);
}
```

React передаёт в эту функцию актуальное предыдущее значение. Это важно при нескольких обновлениях подряд.

## Правила хуков

Хуки вызываются на верхнем уровне компонента: не внутри `if`, `for` или обработчика события. Их порядок должен быть одинаковым при каждом рендере. Хуки вызывают внутри React-компонентов или собственных хуков, а не в произвольных обычных функциях.

## Когда нужен state

Храните в состоянии значение, изменение которого пользователь должен увидеть: счётчик, ввод формы, список задач. Не храните отдельно вычисляемые значения, если их всегда можно получить из другого состояния.


## Что означает «снимок состояния»

Каждый вызов компонента получает значения state на момент этого рендера. Обработчик события запоминает эти значения в своём окружении. **Замыкание** — свойство JavaScript-функции сохранять доступ к переменным того окружения, где она была создана.

```jsx
function Counter() {
  const [number, setNumber] = useState(0);

  function handleClick() {
    setNumber(number + 1);
    console.log(number);
  }

  return <button onClick={handleClick}>{number}</button>;
}
```

Если на экране `0`, обработчик читает `number` равным `0` даже после setter. Новое значение появится в следующем рендере. Это не ошибка или задержка JavaScript-переменной: это правило работы React-state.

Если нужно сразу несколько обновлений, зависящих друг от друга, правильнее передавать функцию updater. В следующей лекции разберём очередь обновлений.
