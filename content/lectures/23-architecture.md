# Структура проекта

## Когда одного App.jsx становится недостаточно

По мере роста приложения `App.jsx` может содержать формы, списки, сетевые запросы и навигацию. Такой файл сложно читать и исправлять.

**Разделение ответственности** означает, что каждая часть программы решает понятную задачу. Компоненты отвечают за отображение и действия пользователя, функции работы с API — за HTTP-запросы, файлы CSS — за внешний вид.

Простая структура небольшого проекта:

```text
src/
├── main.jsx
├── App.jsx
├── components/
│   ├── NewTaskForm.jsx
│   └── TaskList.jsx
├── pages/
│   ├── HomePage.jsx
│   └── AboutPage.jsx
├── api/
│   └── tasks.js
└── index.css
```

`components` содержит переиспользуемые части интерфейса. `pages` — экраны, соответствующие адресам. `api/tasks.js` — функции отправки запросов. Такая структура не является обязательным стандартом, но делает местоположение кода предсказуемым.

## Выделение API-функции

Например, `src/api/tasks.js`:

```js
export async function getTasks() {
  const response = await fetch(
    'https://jsonplaceholder.typicode.com/todos?_limit=5'
  );

  if (!response.ok) {
    throw new Error(`HTTP ${response.status}`);
  }

  return response.json();
}
```

Компонент больше не обязан знать точный URL:

```js
import { getTasks } from './api/tasks.js';
```

При изменении адреса API достаточно исправить один файл.

## Переиспользование и разумные границы

Не выделяйте отдельный компонент для каждого `<p>` или `<span>`. Разделение оправдано, если часть имеет самостоятельный смысл, повторяется или затрудняет чтение родителя.

Чем проще приложение, тем проще может быть структура его файлов. Профессиональная архитектура начинается не с большого количества каталогов, а с понятных границ.

## Проверка приложения перед публикацией

Для сборки готовой версии Vite используется:

```bash
npm run build
```

**Сборка** — подготовка оптимизированных файлов для публикации. Результат находится в `dist/`. Проверить его локально можно через:

```bash
npm run preview
```

Сайт-приложение может быть опубликован на статическом хостинге, поддерживающем SPA fallback. Сам React не заменяет серверное API — если приложение получает данные с сервера, этот сервер должен быть доступен и после публикации.

После этого курса вы должны понимать, как создавать React-компоненты, передавать данные, менять состояние, работать с формами, получать информацию по HTTP и организовывать несколько страниц. Третья лабораторная объединит эти возможности в одно приложение.
