# useMemo

## Почему вычисления повторяются

При каждом вызове компонента выполняется его JavaScript-код. Если список большой, сортировка или сложная фильтрация могут оказаться заметными. Но обычная фильтрация десяти задач почти ничего не стоит.

Начнём без оптимизации:

```jsx
function TaskList({ tasks, query }) {
  const visible = tasks.filter((task) => task.title.includes(query));
  return <p>Подходящих задач: {visible.length}</p>;
}
```

`visible` заново вычисляется при каждом рендере. Это корректное и предпочтительное решение, пока измерения не выявили проблему.

## Что такое мемоизация

**Мемоизация** — сохранение результата вычисления для повторного использования при тех же входных данных. `useMemo(calculate, dependencies)` принимает чистую функцию вычисления и массив её реактивных зависимостей.

```jsx
import { useMemo } from 'react';

function TaskList({ tasks, query }) {
  const visible = useMemo(
    () => tasks.filter((task) => task.title.includes(query)),
    [tasks, query]
  );
  return <p>Подходящих задач: {visible.length}</p>;
}
```

При первом рендере React вызывает функцию и сохраняет результат. При следующих React обычно возвращает сохранённый результат, если зависимости не изменились. Когда `tasks` или `query` изменятся, вычисление выполняется снова. Сравнение зависимостей выполняется по `Object.is`: новая ссылка на массив отличается от старой.

**Важно:** `useMemo` — подсказка для оптимизации, а не гарантия пожизненного хранения значения. React имеет право отбросить кеш при определённых обстоятельствах. Корректность компонента не должна зависеть от существования кеша.

## Когда useMemo избыточен

```jsx
const total = tasks.length;
```

Для такого выражения мемоизация не имеет смысла. Она добавит больше кода и работу по сравнению зависимостей. Иногда даже `filter` на небольшом наборе дешевле простой логики кеширования. Нельзя использовать `useMemo` вместо исправления бесконечного рендера или ошибки Effect.

## Связь с React.memo

`useMemo` может удерживать ссылку на результат, например отфильтрованный массив, который передаётся в `memo`-компонент. Это полезно только если и сама работа дочернего компонента дорога, и зависимости стабильно сохраняются.

Современный **React Compiler** может автоматически мемоизировать вычисления и компоненты в проектах, где он настроен. В таком случае ручные `useMemo` часто не нужны. Vite-шаблон сам по себе не означает, что Compiler обязательно включён.

Документация: [useMemo](https://react.dev/reference/react/useMemo), [React Compiler](https://react.dev/learn/react-compiler).
