# Объекты и массивы в state

## Список задач как state

Ранее мы отображали массив, записанный вне компонента. Чтобы добавлять и удалять задачи, перенесём его в состояние.

`src/App.jsx`:

```jsx
import { useState } from 'react';

export default function App() {
  const [tasks, setTasks] = useState([
    { id: 1, title: 'HTML', done: true },
    { id: 2, title: 'React', done: false }
  ]);

  function addTask() {
    const nextTask = {
      id: crypto.randomUUID(),
      title: 'Новая задача',
      done: false
    };
    setTasks((previous) => [...previous, nextTask]);
  }

  return (
    <main>
      <p>Всего задач: {tasks.length}</p>
      <button onClick={addTask}>Добавить</button>
      <ul>
        {tasks.map((task) => <li key={task.id}>{task.title}</li>)}
      </ul>
    </main>
  );
}
```

`crypto.randomUUID()` — встроенная возможность современных браузеров для создания практически уникального строкового идентификатора. Каждый `key` остаётся стабильным для своей задачи.

## Почему нельзя изменять исходный массив

Не пишите `tasks.push(nextTask)`. Это изменяет уже существующий массив и нарушает модель «состояние — снимок». React ожидает новое значение состояния. Конструкция `[...previous, nextTask]` создаёт новый массив со старыми элементами и новой задачей.

## Удаление

Для удаления используется `filter`, который мы уже изучали:

```jsx
function removeTask(id) {
  setTasks((previous) =>
    previous.filter((task) => task.id !== id)
  );
}
```

Чтобы вызвать функцию с идентификатором, внутри `map` добавьте:

```jsx
<li key={task.id}>
  {task.title}
  <button onClick={() => removeTask(task.id)}>Удалить</button>
</li>
```

## Обновление объекта

Чтобы отметить задачу выполненной, используем `map` и создадим новый объект только для нужного `id`:

```jsx
function toggleTask(id) {
  setTasks((previous) =>
    previous.map((task) =>
      task.id === id ? { ...task, done: !task.done } : task
    )
  );
}
```

`map` создаёт новый массив. У совпавшей задачи spread копирует свойства; `done` заменяется на противоположное. Остальные объекты остаются без изменений.

Количество выполненных задач теперь можно вычислить, не создавая ещё один state:

```js
const completed = tasks.filter((task) => task.done).length;
```

Такое значение называется **вычисляемым**: оно однозначно определяется исходным состоянием.


## Почему иммутабельность важна

**Иммутабельность** означает, что вместо изменения существующего значения создаётся новое. В React это не запрет на любые изменения переменных JavaScript, а правило обращения к значениям props и state при рендере. Если написать `task.done = true` в старом массиве, предыдущий снимок состояния будет изменён, что усложняет сравнение и может привести к неожиданному интерфейсу.

Новый объект `{ ...task, done: true }` сохраняет старое значение нетронутым. Для вложенных объектов одного поверхностного копирования может быть недостаточно: копировать нужно каждый уровень, который меняется.

```js
const oldTask = { id: 1, info: { priority: 'low' } };
const nextTask = {
  ...oldTask,
  info: { ...oldTask.info, priority: 'high' }
};
```

Здесь мы создали новый `info`, а не поменяли старый. Прямую мутацию нельзя использовать как способ сообщить React о новом state.
