# Props и children

## Одному компоненту — разные значения

**Props** (свойства компонента) — значения, которые родитель передаёт дочернему компоненту через атрибуты JSX. В отличие от локальных переменных, props задаются снаружи.

`src/TaskCard.jsx`:

```jsx
export default function TaskCard({ title, done }) {
  return (
    <article>
      <h2>{title}</h2>
      <p>{done ? 'Выполнено' : 'В работе'}</p>
    </article>
  );
}
```

`{ title, done }` в параметрах функции — изученная ранее деструктуризация объекта. React передаёт объект props, а эта запись извлекает нужные свойства.

`src/App.jsx`:

```jsx
import TaskCard from './TaskCard.jsx';

export default function App() {
  return (
    <main>
      <h1>Мои задачи</h1>
      <TaskCard title="Повторить HTML" done={true} />
      <TaskCard title="Изучить React" done={false} />
    </main>
  );
}
```

Значение строки передаётся в кавычках, а JavaScript-значение — в `{}`. React покажет две карточки с разными статусами.

## Почему props нельзя изменять в дочернем компоненте

Props — входные данные. Родитель отвечает за их выбор. Дочерний компонент должен только показывать полученные значения и не присваивать новое значение полученному объекту. Такой подход называется **однонаправленным потоком данных**: информация передаётся сверху вниз.

## Вложенный интерфейс: children

Иногда родитель должен передавать не строку, а разметку между открывающим и закрывающим тегами. React предоставляет специальный prop `children`:

```jsx
function Panel({ children }) {
  return <section className="panel">{children}</section>;
}

export default function App() {
  return (
    <Panel>
      <h1>Мои задачи</h1>
      <p>Учебное приложение</p>
    </Panel>
  );
}
```

`Panel` не знает заранее, что находится внутри, и подходит для разных экранов. Это пример композиции.

Следующий шаг — выводить карточки не по одной вручную, а из массива задач.

## Кто владеет данными

Props не являются общей изменяемой областью памяти между родителем и ребёнком. Родитель создаёт JSX с входными данными; ребёнок получает их и вычисляет своё отображение. Если ребёнку нужно сообщить о действии, родитель может передать функцию-обработчик через prop. Мы подробно изучим такие обработчики после темы событий.

Понятие **деструктуризации** полезно для чтения `function Card({ title })`: React фактически передаёт один объект props, а эта запись извлекает из него `title`. Эквивалентная запись — `function Card(props) { return <h2>{props.title}</h2>; }`. Оба варианта корректны.

## Разница между children и обычным prop

`title="Заголовок"` передаёт конкретное строковое значение. Между `<Panel> ... </Panel>` можно разместить целый кусок JSX — React передаст его как `children`. Это позволяет компоненту `Panel` управлять рамкой, отступами и общей разметкой, не зная заранее содержимое панели.

**Типичная ошибка:** считать, что изменения props внутри ребёнка автоматически изменят состояние родителя. Нет: данные идут сверху вниз. Для изменения данных нужен явный путь уведомления родителя, который мы реализуем в лекции о поднятии состояния.
