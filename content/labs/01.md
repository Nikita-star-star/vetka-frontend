# Лабораторная работа №1. Каталог задач

## Постановка задачи

Создайте небольшое React-приложение «Каталог задач». Оно должно показывать несколько заранее подготовленных задач. На этом этапе задачи **не изменяются пользователем**: цель — научиться строить интерфейс из компонентов и данных.

Работа выполняется после лекции «Списки и условный вывод». Для выполнения используются только изученные HTML, CSS, JavaScript, JSX, компоненты и props.

## Требования

1. Приложение создано через Vite.
2. Заголовок страницы — «Мои задачи».
3. В отдельном массиве есть не менее шести объектов задач.
4. Каждая задача содержит `id`, `title`, `description`, `done` и `priority`.
5. В отдельном компоненте `TaskCard` отображаются заголовок, описание, приоритет и статус.
6. В отдельном компоненте `TaskList` массив преобразуется в список элементов.
7. Для элементов списка применён стабильный `key`.
8. Когда массив пустой, показывается «Задач пока нет».
9. Интерфейс имеет аккуратные CSS-стили и корректно отображается на телефоне.

## Рекомендуемая структура

```text
src/
├── main.jsx
├── App.jsx
├── TaskCard.jsx
├── TaskList.jsx
├── tasks.js
└── App.css
```

`tasks.js` хранит массив, `TaskCard.jsx` — одну карточку, `TaskList.jsx` — список, `App.jsx` объединяет страницу.

## Порядок выполнения

1. Создайте React-проект через Vite и убедитесь, что он запускается.
2. Удалите демонстрационный интерфейс из `App.jsx`.
3. Создайте массив задач в `tasks.js` и экспортируйте его.
4. Создайте `TaskCard`, которая получает props и показывает одну задачу.
5. Создайте `TaskList`, которая принимает массив через props.
6. Реализуйте отображение карточек через `map`. Внешний HTML-список должен содержать элементы `<li>`; внутри них можно расположить карточки.
7. Добавьте обработку пустого массива через условный рендеринг.
8. Создайте стили: ограничение ширины контейнера, отступы, читаемые заголовки, различимый статус.
9. Проверьте проект на большом и маленьком экране.

## Подсказки

Формат одного объекта:

```js
{
  id: 1,
  title: 'Повторить HTML',
  description: 'Изучить семантические теги',
  done: false,
  priority: 'medium'
}
```

Для массива карточек используйте `map`; для статуса — тернарный оператор. `priority` пока можно отображать простой строкой.

## Ожидаемый результат

На странице отображается заголовок и шесть разных карточек. При изменении массива в исходном файле число карточек меняется без копирования JSX. Если передать пустой массив, вместо карточек появляется сообщение.

## Критерии проверки

- Все требования выполнены.
- Компоненты не дублируют код карточек.
- Данные поступают в компоненты через props.
- `key` уникален для каждой задачи.
- Проект запускается без ошибок.
- Стили не мешают чтению и не создают горизонтальный скролл всей страницы.

## Контрольные вопросы

1. Почему компонент удобнее копирования одинаковой разметки?
2. В чём отличие props от локальной переменной?
3. Зачем списку нужен `key`?
4. Почему `map` подходит для формирования JSX-элементов?
5. Как React определяет, что вместо списка нужно показать сообщение об отсутствии задач?
