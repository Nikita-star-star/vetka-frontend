# Лабораторная работа №1. Компонентный интерфейс

## Цель работы

Создать первоначальную версию React-приложения с JSX, повторно используемыми компонентами, props, композиционной структурой, условным отображением и выводом массива.

## Постановка задачи

Разработайте статический каталог объектов в выбранной предметной области. «Статический» означает, что пользователь пока не изменяет данные через интерфейс. На этом этапе важно научиться превращать массив данных в последовательность компонентов и отделять оформление от содержимого.

## Исходные данные

Пройдены лекции 1–7 включительно. Необходимы Node.js, npm, Vite, базовый JavaScript, HTML и CSS. Данные для каталога студент придумывает самостоятельно: не менее **12 объектов**, минимум четыре заполненных поля и стабильный `id` для каждой записи. Внешний API в первой работе не нужен.

## Единая модель проекта

Во всех вариантах предусмотрена коллекция однотипных объектов со стабильным `id`, компонент карточки, компонент списка, минимум два смысловых свойства для отображения и одно условное свойство для статуса. Студент выбирает предметную область **один раз** в первой лабораторной и продолжает **тот же проект** во второй и третьей, сохраняя данные, компоненты и CSS. Менять предметную область между работами нельзя без согласования с преподавателем.

Предметные различия не меняют объём обязательной реализации: каждый студент должен продемонстрировать сопоставимый набор механизмов React. Если в тематике нет естественного аналога корзины или избранного, используется действие «добавить в личный список / удалить из личного списка». Это действие не требует регистрации или серверной базы данных.
## Рекомендуемая структура

```text
src/
├── main.jsx
├── App.jsx
├── data/
│   └── items.js
├── components/
│   ├── ItemCard.jsx
│   ├── ItemList.jsx
│   └── PageShell.jsx
└── styles.css
```

Названия `ItemCard` и `ItemList` универсальны; допустимы предметные имена (`ProductCard`, `BookList`), но выбранные имена далее должны использоваться последовательно. Уже в первой работе следует отделить исходные данные от отображения. Это позволит во второй работе заменить статический массив на state, а в третьей — добавить загрузку через API без полного переписывания интерфейса.

## Функциональные требования для всех вариантов

1. Главный экран содержит заголовок, краткое описание тематики и коллекцию объектов.
2. Для каждого объекта отображается минимум три поля: название и два содержательных свойства.
3. Одно логическое поле влияет на вывод статуса («в наличии», «прочитано», «места есть», «доступен» и т. п.).
4. Если массив пуст, отображается текст «Записей нет» или предметно подходящий аналог.
5. Данные всех 12 объектов передаются в интерфейс из одного массива, а не копированием карточки вручную.
6. Интерфейс остаётся читабельным при ширине 360 px: горизонтальная прокрутка всей страницы отсутствует.
7. Элементы управления, если они нарисованы, не должны изображать готовую интерактивность. В первой работе допустимо ограничиться статической карточкой без кнопок.

## Технические требования

- React-приложение создано через Vite.
- Есть корневой `App`, отдельные компоненты карточки и списка.
- Данные передаются через props. Повторяющаяся разметка не копируется вручную.
- Коллекция отображается с помощью `map`; каждому корневому элементу списка задаётся стабильный `key` по `id`.
- Используется условный рендеринг.
- `children` применяется для общей обёртки интерфейса, если это уместно, например для общего контейнера `PageShell`.
- Стили — обычный CSS; обязательных UI-библиотек нет.

## Предметные требования

| Вариант | Что должна показывать карточка | Условный статус | Что означает пустой список |
|---|---|---|---|
| Интернет-магазин | название, стоимость, категория, наличие | Есть в наличии / нет | Коллекция не содержит записей. |
| Планировщик задач | название, описание, статус, приоритет | Выполнена / не выполнена | Коллекция не содержит записей. |
| Каталог фильмов | название, жанр, год, рейтинг | Добавлен / не добавлен | Коллекция не содержит записей. |
| Библиотека книг | название, автор, жанр, статус прочтения | Прочитана / не прочитана | Коллекция не содержит записей. |
| Платформа мероприятий | название, дата, место, категория | Места есть / нет | Коллекция не содержит записей. |
| Каталог курсов | название, направление, уровень, длительность | Открыт / закрыт | Коллекция не содержит записей. |

## Методические указания

1. Создайте приложение командой `npm create vite@latest <имя-проекта> -- --template react`, затем установите зависимости и запустите проект.
2. Уберите демонстрационные элементы Vite. Убедитесь, что `App.jsx` возвращает небольшой корректный JSX.
3. Определите модель одного объекта: `id`, название и минимум три свойства, соответствующие выбранной предметной области. Для всей коллекции используйте одинаковые имена полей.
4. Запишите 12 объектов в массив `items` в `data/items.js` и экспортируйте его.
5. Создайте `ItemCard`, которая принимает один объект через props. Не копируйте карточку для каждого объекта отдельно.
6. Создайте `ItemList`, которая принимает массив, отображает карточки через `map` и показывает пустое состояние, когда элементов нет.
7. Добавьте компонент общей оболочки или контейнер без лишней вложенности. Если используете `children`, покажите, какую повторяемую разметку он устраняет.
8. Подключите CSS: контейнер, отступы, текст, сетка карточек, видимый статус. Не используйте цвет как единственный способ различать статус.
9. Замените массив временно на `[]` и убедитесь, что отобразится пустое состояние. Верните исходный массив.
10. Проверьте консоль разработчика: предупреждения о `key`, ошибки импорта и нарушения HTML-вложенности отсутствуют.

**Подсказка о модели:**

```js
const item = {
  id: 1,
  title: 'Объект каталога',
  category: 'Категория',
  active: true,
  description: 'Короткое описание'
};
```

Это только пример формы данных. Адаптируйте названия полей под выбранную тему и не копируйте в проект условный объект буквально. Подсказка по списку: `items.map((item) => <ItemCard key={item.id} item={item} />)`; сам компонент и оформление напишите самостоятельно.

## Требования к сдаче

Работающий исходный проект, запускаемый через `npm run dev`. Преподаватель должен иметь возможность проверить, что изменение одного объекта в файле данных изменяет ровно одну карточку, а пустой массив показывает сообщение. Подготовьте короткое устное объяснение структуры компонентов.
